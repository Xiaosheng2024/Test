# EHX 下线防错程序 - 管理员部署说明

## 环境要求

- Windows 10/11 64 位。
- Microsoft Excel 已安装并能正常启动。
- 现场打印机驱动已安装，Windows 测试页打印正常。
- 程序目录对当前用户可写。

程序默认使用代码生成的 Code128 PNG，不需要安装条码字体，也不需要安装额外的
PDF 转换或静默打印软件。

## 部署

1. 解压 `EHX下线防错_Windows.zip`。
2. 保持 EXE、`config.json`、物料表和模板位于同一目录。
3. 在 `config.json` 中设置 `printer_name`：
   - 留空：使用 Windows 默认打印机。
   - 非空：必须填写 Windows 打印机的完整名称。
4. 配置扫码枪：
   - 现场默认使用串口模式。
   - HID：`scanner_mode` 填 `hid`，默认切换英文键盘布局，且光标不在扫码框也能在本程序内接收。
   - 串口：`scanner_mode` 填 `serial`，配置 `serial_port` 和 `serial_baudrate`。
     新大陆 NLS-OY20-RF 默认使用 9600/8/N/1/无流控，支持 CR、LF、CRLF 结束符。
     如 Windows 设备管理器未出现 COM 口，先安装/检查 USB 虚拟串口驱动。
   - 也可启动后点击右上角“设置”保存并立即应用。
5. 确认 `box_scan_count`、产线名称和工位名称正确。
6. 运行 `EHX下线防错.exe`。

HID 无光标接收默认仅覆盖本程序窗口。如要求程序退到后台后仍接收，需单独做 Windows Raw Input 设备绑定和现场验收。

## 物料表与每箱数量

`EHX物料号匹配.xlsx` 必须使用以下列：

| 列 | 字段 |
| --- | --- |
| A | 扫码条码的固定物料前缀，例如 `5664620FA2#01` |
| B | 物料名称 |
| C | 客户物料号/SAP物料号 |
| D | 每箱数量 |

A 列必须填写完整扫码条码开头不变化的物料部分。程序按
`完整扫码条码.startswith(Excel A列物料码)` 识别物料。例如：

```text
Excel A列：5664620FA2#01
完整条码：5664620FA2#01#20260701#0001
```

后面的 `#20260701#0001` 是日期和流水号，只用于单件唯一性以及完整条码重复判断，
不参与物料配置。同箱防错按 Excel A 列识别出的物料码判断，不允许不同前缀混扫。
A 列前缀由 Excel 维护，程序中不写死。

程序已支持 `#yyyyMMdd#4位流水号` 新格式，同时兼容旧格式
`yyyyMMdd + 3位流水号`。重复判断始终使用完整扫码条码。

D 列为空时使用 `config.json` 中的全局 `box_scan_count`；填写时必须是大于 0 的
整数。第一件扫码后，当前箱按对应物料的 D 列数量进行满箱校验。该数量会写入历史
下线单，不会因以后修改 Excel 而改变。

新箱尚未扫描首件时数量显示为 `0/--`，首件识别物料后才锁定该箱数量。

修改 Excel 后，可在主界面打开“物料查看 / 重新导入”并点击“重新导入物料”，
界面会显示新增、更新、禁用数量；也可以重启程序自动同步。

## MII 报产配置

默认 `mii_enabled=false`，程序不访问 MII。启用前必须确认 Fang 工或客户提供的
正式 MII 地址和主数据。

核心规则：

- 满箱后只报产一次，不是一件一传。
- Excel C 列 `客户物料号/SAP物料号` 作为 MII `PartNumber`。
- 当前箱 `required_count` 作为 MII `Quantity`。
- `HUCode` 参数传空，让 MII 自动生成。
- 返回 `Status=PRODUCED` 且有 `HUCode` 才算成功。
- 完整 `HUCode` 保存到数据库；`S + HUCode后9位` 打印到“批次号 / 下线单号”位置和条码。
- 报产失败不自动连续重拨，不打印，订单停在 `MII_FAILED`，需人工限流重试。

需要配置：

```json
{
  "mii_enabled": true,
  "mii_base_url": "https://wwvcamii0071.dc.ege.ds:50001/XMII/",
  "mii_transaction": "SC_AUTOMATION/API/PRODUCTION/V1/TRANSACTION/PRODUCTION_API",
  "mii_output_parameter": "ResultXML",
  "mii_login_name": "",
  "mii_login_password": "",
  "mii_plant": "",
  "mii_user_id": "",
  "mii_customer_code": "",
  "mii_production_version": "0001",
  "mii_production_shift": "",
  "mii_workcenter": "",
  "mii_packaging_material": "",
  "mii_information_mode": "offline_order_no",
  "mii_information": "",
  "mii_produce_reverse": "P",
  "mii_content_type": "text/xml",
  "mii_timeout_seconds": 10,
  "mii_min_retry_interval_seconds": 60,
  "mii_max_retry_count": 3
}
```

以上字段可在程序右上角“设置”→“MII接口”中保存并立即生效。
MII 开关默认关闭，测试时由管理员手动勾选“启用整箱 MII 报产”。
MII 密码以明文保存在本机 `config.json`，应限制交付目录权限。
`PartNumber`、`Quantity`、`ProductionDate` 由程序动态生成，`HUCode` 请求时传空。

历史查询支持完整 HU、`S+后9位` 和裸后9位，可追溯对应整箱的所有扫码记录。

可在 PowerShell 中查看打印机完整名称：

```powershell
Get-Printer | Select-Object Name
```

正式打印使用 Microsoft Excel COM：

```text
printer_name 为空  -> worksheet.PrintOut()
printer_name 非空  -> worksheet.PrintOut(ActivePrinter=printer_name)
```

如果指定打印机不存在或打印失败，程序不会删除 PDF 或同名 XLSX，数据库订单状态会
记录为 `PRINT_FAILED`，GUI 会显示失败原因。修正打印机配置后，可在历史记录中补打。

## 必需的同级文件

- `EHX下线防错.exe`
- `config.json`
- `EHX物料号匹配.xlsx`
- `报交下线单模板.xlsx`

GitHub Actions 打包时会把配置、物料表和模板复制到 EXE 同级的交付目录根目录。
程序以 EXE 所在目录为基准解析 `config.json` 及其中的相对路径，不依赖构建机或
开发电脑的绝对路径。

## 验收

1. 执行正常、重复、混料、未配置和格式错误扫码测试。
2. 扫满一箱，确认生成单页 A5 横向 PDF。
3. 检查纸面物料号、客户料号和下线单号条码可扫描。
4. 模拟打印失败，确认 PDF、XLSX 和数据库记录仍保留。
5. 在历史查询中打开 PDF 并执行补打。

## 数据目录

- `data/`：SQLite 数据库。
- `logs/`：运行与错误日志。
- `output/pdf/`：PDF 和同名 XLSX 留档。
- `output/barcodes/`：程序生成的 Code128 PNG。

程序直接使用 SQLite，不依赖外部数据库管理工具。
